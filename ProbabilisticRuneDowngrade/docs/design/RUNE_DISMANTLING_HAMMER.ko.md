# 전용 룬 분해 망치 설계

이 문서는 0.2.0에서 구현한 전용 망치의 원래 설계 기록입니다. 현재 1.0.0의 사용법·제작·판매 옵션은 [README](../../README.md), 실제 검증 상태는 [TESTING](../TESTING.ko.md)을 참고하세요. 아래의 조사·미구현 표현은 원래 설계 시점 기준입니다.

## 목적

다른 모드가 같은 룬 + 감별 주문서 조합을 사용하는 경우와 구분하기 위해 전용 분해 재료를 도입한다. 현재의 두 단계 조합, 32등급 지원, 추첨값 저장 및 네 가지 확률 구조를 유지한다. 전용 재료는 구체적인 입력 조합의 충돌을 줄이지만, 모든 아이템을 받는 광범위한 외부 조합법이나 아이템 코드 충돌까지 없앤다고 보장하지 않는다.

## 확정 요구사항

| 항목 | 요구사항 |
|---|---|
| 판매 NPC | 액트 1의 기드 |
| 지원 난이도 | 보통·악몽·지옥 모두 판매 |
| 구매 가격 | 1골드 |
| 판매 가격 | 1골드 |
| 중첩 | 불가. 1개씩 독립 아이템 |
| 소모 방식 | 첫 조합에서 룬과 망치 각 1개 소비 |
| 첫 조합 | 룬 1개 + 분해 망치 1개 → 추첨값이 저장된 분해 대기 아이템 |
| 두 번째 조합 | 대기 아이템만 단독으로 조합. 추가 재료 없음 |
| 꽝 결과 | 감별 주문서 대신 분해 망치 1개 지급 |
| 재료 이미지 | 기존 호라드림 망치 이미지를 수정해 사용 |
| 대상 룬 | 엘드~조드 전체 32등급. 엘은 분해 불가 |

호라드림 망치는 이미지의 바탕으로만 사용한다. 실제 퀘스트 아이템을 재료로 요구하거나 기존 퀘스트 아이템의 코드·기능·판매 설정을 변경하지 않는다. 별도 비퀘스트 아이템으로 정의한다.

## 결과와 확률

| 두 번째 조합의 결과 | 기본 확률 | 분해 망치 |
|---|---:|---|
| 바로 아래 등급 룬 2개 | 50% | 반환하지 않음 |
| 바로 아래 등급 룬 1개 | 25% | 반환하지 않음 |
| 입력 룬 1개 반환 | 10% | 반환하지 않음 |
| 꽝: 분해 망치 1개 | 15% | 1개 지급, 입력 룬은 소실 |

네 확률은 기존처럼 각각 0~100 정수이며 합계가 정확히 100이어야 한다. 전 등급에서 두 개 당첨은 2개를 지급한다. 두 번째 조합은 새 추첨을 하지 않는다. 첫 조합에서 망치를 돌려주거나 꽝에서 룬과 망치를 함께 지급하는 설계가 아니다.

## 제안 사항 — 아직 확정 아님

- 표시 이름: **룬 분해 망치 / Rune Dismantling Hammer**.
- 인벤토리 크기: 사용 편의를 위한 1×1을 우선 검토. 기존 망치 원본의 크기를 그대로 따른다는 요구는 아니다.
- 전용 고유 3글자 코드와 종류를 사용하고 misc/armor/weapons 및 HD 매핑의 충돌을 검사한다. 실제 코드는 구현 시 결정한다.
- 기드의 재고가 소진되지 않고 계속 구매 가능한 판매 방식을 우선 검토한다. 비중첩과 판매 재고 정책은 별개다.
- 드롭 획득·다른 NPC 판매·재사용 도구·겹치기 기능은 이번 범위에 포함하지 않는다.

## 구현 범위

1. **새 재료 정의:** misc/itemtypes, 이름·설명 문자열 및 그래픽 참조를 추가한다. 무작위 추첨 스탯은 이 재료에 추가할 필요가 없다.
2. **판매 설정:** 기드의 판매 관련 필드·난이도별 동작을 확인하고 새 재료에만 적용한다. 상점 전체나 기존 아이템의 가격을 변경하지 않는다.
3. **조합 변경:** 32개 첫 단계 조합에서 감별 주문서를 새 재료로 교체한다. 두 번째 단계의 꽝 출력만 망치로 교체하며 나머지 결과·수량·확률은 유지한다. 기존 룬+주문서 조합은 우리 모드에서 더 이상 추가하지 않는다.
4. **보존 대상:** 대기 아이템 코드, 저장 추첨값 형식, 스탯, 기존 Relics 호환 처리를 유지하는 방향으로 구현한다. 새 재료를 위해 별도 저장 스탯을 추가하지 않는다.
5. **이미지:** 일반 퀘스트 망치를 덮어쓰지 않도록 별도 경로를 사용한다. 0.1.1의 빛나는 대기 룬 아이콘과 바론9 크레딧은 유지한다. 새 망치의 일반·저해상도 HD와 클래식 표시 방식은 자산 확인 후 정한다.
6. **표시·문서·배포물:** 설정의 꽝 설명, 한국어 README, 영문/한글 Nexus 원고, 크레딧, 변경 이력, 자동 검증 및 ZIP 포함 파일을 갱신한다. 다음 버전 번호는 구현 시 결정한다.

## 구현 전 확인 사항

### 참고 모드 및 자산

Corruption Shards for RoTW / rogeriogmm: https://www.nexusmods.com/diablo2resurrected/mods/1051

이 설계 작성 시 해당 모드 ZIP은 아직 제공되지 않았고, 클라우드의 Nexus 접근은 프록시 403으로 차단돼 있다. 따라서 참고 모드의 실제 상점·재료 소모 구현을 확인했다고 주장하지 않는다. ZIP을 받으면 구조를 참고하되, 코드·이미지·파일을 복사하려면 각각의 권한을 확인한다. 사용자가 전달한 rogeriogmm의 답변에서 제안 크레딧 동의와 필요시 코드 사용 허락을 확인했다. 이번 구현은 해당 모드 코드를 사용하지 않았다.

공개 호라드림 망치 PNG를 참고해 AI 지원으로 청록색의 짧은 망치 아이콘을 제작했고 사용자가 승인했다. 98×98/49×49 sprite로 변환하여 픽셀·투명도 보존을 확인하고 모드에 연결했다. 게임 원본 자산과 다른 제작자의 수정 이미지는 출처·사용 조건을 구분한다.

### 구매·판매 가격

요구사항은 **구매와 판매 모두 1골드**다. `cost=1`만 설정하면 충족된다고 가정하지 않는다. 상점 가격 계산·반올림·난이도·흥정 효과 등에 따라 실제 표시와 지갑 증감이 달라질 수 있으므로 확인이 필요하다.

다른 아이템에 영향을 주지 않는 데이터 설정으로 정확히 구현할 수 있는지 조사한다. 구현 불가나 엔진 제약이 확인되면 그 근거와 대안을 보고하고, 사용자 결정 없이 0골드·다른 가격으로 바꾸거나 광범위한 상점 변경을 도입하지 않는다. 다른 NPC에 되팔 때의 가격 범위도 확인한다.

### 기존 세이브와 대기 아이템

업데이트 전 대기 아이템을 모두 처리하고 캐릭터·공유 보관함을 백업한다. 기존 대기 아이템을 남긴 채 업데이트하면 저장 추첨값의 꽝 결과가 주문서에서 망치로 바뀔 수 있으므로 이를 숨기지 않는다. 코드·저장 형식을 유지하더라도 구버전 세이브 호환성은 실제 검증 없이 보장하지 않는다.

## 검증 기준

- 자동 검사로 모든 등급의 첫 입력이 전용 망치인지 확인하고, 모든 추첨값에서 확률별 출력·수량이 맞는지 검사한다.
- 기존 룬+주문서 조합을 우리 모드가 생성하지 않는지, 새 아이템 코드 충돌 시 설치가 중단되는지 확인한다.
- 새 재료가 비중첩·비퀘스트이며, 기존 일반 룬과 퀘스트 망치 데이터가 보존되는지 확인한다.
- 보통·악몽·지옥의 기드에게 표시·구매·재구매가 가능한지 실제 게임에서 확인한다.
- 구매·판매 시 화면 가격과 실제 골드 증감이 모두 1인지 확인한다. 흥정 효과와 다른 NPC 되팔기에서의 차이도 기록한다.
- 각 결과 100% 테스트에서 망치 소비·꽝 반환·룬 지급 수량을 확인한다. 기본값 및 한 옵션만 0%인 네 설정도 검사한다.
- 재료·대기 아이템의 인벤토리·바닥·저장/재접속 표시 및 대기 아이템 단독 재조합을 확인한다.
- 병용 환경에서 기드 판매·기존 모드의 주문서 조합과 함께 사용할 수 있는지 확인한다.
- 두 ZIP에 새 자산·필요한 크레딧이 빠짐없이 포함되는지 검사한다. 자동 검사와 실제 게임 결과를 구분해 기록한다.

## 브랜치 및 배포 경계

이 브랜치에서는 설계부터 검토한다. 설계 문서 추가는 구현 완료나 테스트 통과를 의미하지 않는다. 기능은 이 브랜치에서 구현하고 사용자 요청에 따라 0.2.0으로 main에 병합한다. Nexus 공개는 이번 작업에 포함하지 않는다.

이 파일은 docs/design/ 아래에 둔다. 현재 빌드 도구는 docs/ 바로 아래 파일만 문서 ZIP에 포함하므로 이 기능 설계서는 설치 ZIP에 포함되지 않는다.
